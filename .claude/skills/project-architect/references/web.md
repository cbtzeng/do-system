# 軟體/Web 系統開發 技術範本

## 典型分層與職責
- **前端**：使用者介面、狀態管理、與 API 溝通。SPA（React/Vue）或 SSR（Next.js/Nuxt）。
- **後端 API**：商業邏輯、驗證、權限、資料存取。RESTful 或 GraphQL。
- **資料層**：關聯式（PostgreSQL/MySQL）為主，快取（Redis），非結構化視需要（檔案儲存/物件儲存）。
- **基礎設施**：部署（容器/雲端 PaaS）、CI/CD、監控、備援。
- **第三方**：金流、簡訊/Email、登入（OAuth）、地圖、客服等。

## 技術選型參考
| 需求情境 | 建議方向 |
| 快速上線、團隊小 | Next.js 全端 + 託管資料庫（Supabase/PlanetScale）+ Vercel/Render |
| 複雜商業邏輯、需長期維護 | 前後端分離，後端 Node(NestJS)/Python(FastAPI/Django)/Go，獨立部署 |
| 高併發/高擴充 | 微服務或模組化單體 + 訊息佇列 + 水平擴充 + CDN |
| 重後台/內部系統 | 低程式碼或成熟 admin 框架，減少前端工 |

## 常見模組清單（拆解起點）
- 基礎建設：專案初始化、CI/CD、環境配置、共用 UI 元件庫
- 帳號權限：註冊/登入、第三方登入、角色權限(RBAC)、密碼/驗證
- 核心業務模組：依專案而定，逐一列出
- 後台管理：資料 CRUD、儀表板、報表匯出
- 金流/訂閱：串接、發票、對帳
- 通知：Email/SMS/站內通知/推播
- 檔案處理：上傳、儲存、預覽、轉檔
- 搜尋：關鍵字、篩選、全文檢索
- 串接：與既有系統或第三方 API 介接
- 測試與上線：自動化測試、部署、驗收

## 複雜度判準
- **低**：標準 CRUD、表單、靜態頁、用成熟套件就能完成、無外部整合。
- **中**：含商業邏輯/狀態流轉、單一外部整合、需自訂 UI、有權限差異。
- **高**：多系統整合、即時(WebSocket)、複雜權限/工作流、效能或一致性敏感、規格不確定性高。
