# App/行動應用 技術範本

## 典型分層與職責
- **客戶端 App**：原生（Swift/Kotlin）或跨平台（React Native/Flutter）。
- **後端 API**：與 Web 類似，提供 App 所需資料與邏輯。
- **推播/即時**：FCM/APNs 推播、WebSocket 即時功能。
- **裝置能力**：相機、定位、生物辨識、藍牙、離線儲存。
- **上架與發布**：App Store / Google Play 帳號、審查、版本管理、OTA 更新。

## 技術選型參考
| 需求情境 | 建議方向 |
| 雙平台、預算有限、UI 標準 | Flutter 或 React Native，一套碼雙平台 |
| 重度原生功能/效能 | 原生開發（Swift + Kotlin），成本約 1.8–2 倍 |
| 已有 Web 後端 | 沿用後端，App 只做客戶端 + 必要 API 調整 |
| MVP 快速驗證 | 跨平台 + 託管後端(BaaS)，先求快 |

## 常見模組清單（拆解起點）
- 基礎建設：專案初始化、設計系統、導航架構、CI/CD（含雙平台打包）
- 帳號：註冊/登入、第三方/生物辨識登入
- 核心功能模組：依 App 而定，逐一列出
- 推播通知：整合與情境設計
- 裝置功能：相機/定位/離線等，逐項列（整合成本高）
- 後端 API：對應各功能的伺服端
- 上架發布：商店帳號設定、審查素材、送審、版本管理
- 測試：雙平台測試、實機測試

## 複雜度判準
- **低**：標準清單/表單/詳情頁、用既有元件、無裝置原生能力。
- **中**：自訂 UI/動畫、單一裝置能力整合、推播、離線快取。
- **高**：複雜裝置整合（藍牙/AR/背景定位）、即時通訊、雙平台原生差異大、嚴格效能/電量要求。

## 估價提醒
雙平台務必確認是「一套跨平台」還是「兩套原生」，這對工時影響極大。上架審查、實機測試、各機型相容性常被低估，建議獨立列為模組並給緩衝。
