# 估算基準指引

這份是工時估算的參考基準，目的是讓不同專案、不同時間估出來的數字有一致的依據。基準是「典型中型團隊、一般品質要求」下的參考值，實際應依團隊熟練度與專案脈絡調整，並把調整理由記下來。

## 各複雜度的單模組人天參考

| 複雜度 | 人天區間 | 說明 |
| 低 | 1–3 | 標準 CRUD、表單、靜態頁、用成熟套件、無外部整合 |
| 中 | 4–8 | 含商業邏輯、單一外部整合、自訂 UI、有權限差異 |
| 高 | 9–20+ | 多系統整合、即時功能、複雜工作流、效能/一致性敏感、規格不確定 |

區間取點估時：規格清楚、團隊熟悉 → 取低段；規格模糊、新技術、整合多 → 取高段或超出上限並標註原因。

## 各領域調整係數（乘在基準人天上）

| 領域 | 係數 | 原因 |
| 軟體/Web | 1.0 | 作為基準 |
| App 跨平台 | 1.1–1.3 | 雙平台測試、機型相容、上架 |
| App 雙原生 | 1.8–2.0 | 兩套程式碼 |
| AI/資料 | 1.2–1.5 | 資料品質、輸出品質達標的不確定性 |

## 附加項建議比例（加在模組未稅小計上）

| 項目 | 建議比例 | 取值原則 |
| 專案管理 PM | 10–15% | 專案越大、關係人越多取高 |
| 測試 QA | 10–20% | 品質/合規要求高取高；AI 專案的評估也算這裡 |
| 溝通/驗收修改 | 5–10% | 客戶端不確定性高取高 |
| 風險緩衝 | 10–25% | 規格不明、新技術、AI/資料專案取高（20–25%）；成熟重複型專案取低 |

緩衝不是亂加價，是反映真實不確定性。寧可誠實標高緩衝並向客戶解釋，也不要低估後超支。

## 日費率分級參考（TWD，未稅，僅為佔位，需依實際調整）

| 角色 | 日費率參考 |
| 資深工程師/架構 | 14,000–20,000 |
| 工程師 | 9,000–13,000 |
| 設計師 (UI/UX) | 8,000–12,000 |
| 專案管理 | 10,000–14,000 |

務必與使用者確認實際費率；上表僅在完全沒有資訊時當佔位，並標註「待確認」。
