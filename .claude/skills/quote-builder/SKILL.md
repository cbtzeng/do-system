# 報價產生 (Quote Builder)

把內部估算包裝成讓客戶願意買單的正式文件。報價文件有兩個目的：讓客戶看懂價值（簡報），以及作為正式商務依據（報價單）。兩者內容一致但呈現不同。

## 兩種交付物

1. **PDF 報價單** — 正式、可簽署的商務文件。重點是精確、完整、有法律效力的條款。用 **pdf skill** 產製。
2. **pptx 提案簡報** — 給客戶簡報用。重點是說故事、凸顯價值、視覺清楚。用 **pptx skill** 產製。

使用者要哪一種就做哪一種；兩種都要時，先確定內容（價格、範圍、時程）一致，再分別產出。

## 開工前先備齊資訊

報價文件代表公司門面，這些資訊缺了就不專業，開始前先確認（一次問完）：

- **公司抬頭**：公司名稱、統編、地址、電話、Email、Logo（有的話）、報價人
- **客戶資訊**：客戶公司/聯絡人、抬頭
- **報價基本資料**：報價單號、報價日期、有效期（常見 30 天）
- **價格內容**：來自 effort-estimator 的模組金額、未稅小計、稅額、含稅總計、工期
- **商務條件**：付款條件、交付時程、保固/維運、條款（可用 `references/quote-templates.md` 的範本）

公司抬頭這類固定資訊，建議第一次填好後存進使用者資料夾（例如 `公司資訊.md`），之後報價直接沿用，不必每次重問。

## PDF 報價單結構

正式報價單一律包含以下區塊，順序固定（客戶習慣由上而下閱讀）：

```
[公司 Logo / 抬頭]              報價單號：Q-YYYYMMDD-NN
                                報價日期：YYYY/MM/DD
                                有效期限：YYYY/MM/DD

報價對象：[客戶公司 / 聯絡人]

專案名稱：[名稱]
專案說明：[1–2 段範圍摘要]

【報價明細】
| 項次 | 項目/模組 | 說明 | 數量(人天) | 單價 | 金額(未稅) |
... 各模組逐列 ...
| 專案管理 / 測試QA / 風險緩衝 ... | 比例 | 金額 |

                              未稅小計：  NT$ ___
                              營業稅 5%： NT$ ___
                              含稅總計：  NT$ ___

【交付時程】預估工期 ___ 個工作天（約 ___ 週），里程碑：...
【付款條件】例如 簽約 30% / 期中 40% / 驗收 30%
【保固與維運】驗收後 ___ 個月保固；維運另議
【備註與條款】見範本
【簽署欄】客戶簽章 / 日期    本公司簽章 / 日期
```

金額一律用 effort-estimator 算好的數字，**不要在報價階段重算**，避免兩份文件對不上。數字以千分位呈現、幣別標 NT$。

## pptx 提案簡報結構

簡報走「問題 → 方案 → 怎麼做 → 多少錢 → 為什麼選我們」的敘事。建議頁序：

1. 封面：專案名稱、客戶、公司、日期
2. 需求理解／痛點：證明你懂客戶要什麼
3. 解決方案概述：一頁講清楚要做什麼
4. 系統架構：放 project-architect 的架構圖
5. 功能模組：分項說明（呼應報價明細）
6. 執行時程：里程碑甘特概念圖
7. 報價：價格表（未稅／稅／含稅），可分方案（基礎/進階）
8. 團隊與優勢／案例
9. 後續步驟與聯絡方式

簡報的報價頁與 PDF 報價單金額必須一致。價值優先於價格——先讓客戶看到能得到什麼，再看到數字。

## 報價單號規則

採 `Q-YYYYMMDD-NN`（NN 為當日流水號），方便日後追蹤。沿用使用者既有編號規則者優先。
